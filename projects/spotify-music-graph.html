Spotify Music Graph Analysis

A group graph-database project that transformed a music dataset into a Neo4j knowledge graph and used Cypher to explore relationships among tracks, artists, albums, and genres.

At a glance

From flat records to relationships

Prepared music data, designed graph relationships, and explored them with Cypher. The documented queries show database modeling and analytical problem-solving in a team project.

Data preparation · Database modeling · Query analysis
7Cypher query tasks
10runtime trials per query
Teamacademic project

Question

How can a graph model make relationships in music data easier to explore than a flat table?

My contribution

I carried out the majority of the project work: preparing the data in Python, organizing track, artist, album and genre records for Neo4j, designing PERFORMED_BY, BELONGS_TO and HAS_GENRE relationships, and analyzing the graph through seven Cypher query tasks.

Tools

Python · Neo4j · Cypher · CSV · Graph Database

Result / insight

The queries explored popular tracks, title keywords, specific artists, upbeat/happy tracks, average popularity by genre, and top-genre counts. Repeated runtime testing also highlighted practical issues around data cleaning and query performance.

Documentation and scope

This was a team project. The repository preserves the original presentation and Cypher queries transcribed from its screenshots. The original Python scripts and CSV files are unavailable; the repository is a reconstruction of the documented work, not a complete reproducible pipeline.

What the work demonstrates

Separating tracks, artists, albums and genres required thinking about entities, identifiers and relationships before querying. Repeating each query ten times produced a record of runtime under the project setup; it is not a benchmark against SQL or a claim of production-scale performance.
